# ПРОМПТ 01. Сбор технических данных

**Цель этапа: не анализировать, а собрать максимально полный сырой массив.**
Ничего не интерпретировать. Ничего не пропускать как «малозначительное».

## Как работает этап

**Основной путь — автоматический.** `jyotish collect clients/<имя>` собирает всё перечисленное ниже сам и записывает `01_RAW_DATA.md`, `01_MISSING_DATA.md` и сводку для этапа 02. Данные переносятся **один в один**, без округлений, с обозначениями сайта. Разбирать экспорт руками не нужно — нужно прочитать `01_MISSING_DATA.md` и понять, чего не хватает.

**Запасной путь — ручной.** Если сбор недоступен (лимит сайта, сбой, нет сети), данные передаёт пользователь: скриншоты вкладок или текстовый экспорт, а ИИ переносит их один в один. Для каждого блока указывается: название вкладки → подраздел → дата получения, чтобы другой астролог мог проверить экспорт.

Отсутствующее помечается дословно:
`НЕДОСТУПНО В ТЕКУЩЕМ ДОСТУПЕ` / `ТРЕБУЕТ ПЛАТНОГО ДОСТУПА` / `ТРЕБУЕТ АВТОРИЗАЦИИ` / `НЕ ПРИСЛАНО ПОЛЬЗОВАТЕЛЕМ`

## 1. Параметры расчёта (фиксируется первым)

Дата · точное время · часовой пояс · место · координаты, фактически использованные сайтом · айанамша · стиль карты · настройка узлов (истинные/средние) · способ расчёта дробных карт · система чара-карак (7 или 8) · настройка арудх · способ расчёта упаграх.

**Статус времени рождения** — указать один из трёх:
- документально подтверждено (свидетельство)
- со слов родственников, ректификация не проводилась
- ректифицировано (указать, кем и по каким событиям)

Этот статус определяет, будут ли доступны Промпт 07 и выводы по D60.

**Айанамша.** Заявленное сайтом число проверено независимо по эфемеридам: оно сходится с айанамшей, по которой посчитаны его собственные положения, до 0.01′. Записывать можно как есть. (Более ранняя версия этого файла утверждала расхождение в 14′ — оно было ошибкой проверки, а не сайта: айанамша отсчитывается от равноденствия на дату карты, а расчёт брал эклиптику J2000.)

**Настройка узлов** тем же способом: сайт её не показывает, но сверка с независимым расчётом сразу говорит, средний узел или истинный (они расходятся до 2° и меняют знак).

## 9. Сила домов

**Бхава-балы vedic-horo не считает,** и она здесь не реконструируется. Собрать её из классических компонентов теоретически можно — Бхавадхипати-бала есть напрямую (это шадбала управителя), — но Бхава-Диг-бала требует таблицы, а Бхава-Дришти-балу не удалось воспроизвести даже для планет: собственную дрик-балу сайт считает по формуле, которая из его же матрицы аспектов не выводится. Синтетическое число, собранное наполовину по памяти, выглядело бы точным и не было бы проверяемым — ровно то, что запрещает `00_README`.

Вместо одного числа собираются **три независимых показателя по каждому дому**, и каждый прослеживается до конкретной цифры сайта:

1. **Бинду САВ** дома — из аштакаварги. Внимание: бинду индексируются **по домам**, а не по знакам; `first_house_sign` говорит, какой знак стоит в первом доме.
2. **Шадбала управителя дома** — классическая Бхавадхипати-бала, в процентах и рупах.
3. **Дришти на дом** — суммы вирупов из матрицы аспектов, разнесённые по натуре аспектирующей планеты. Это сырые числа сайта, **не** Бхава-Дришти-бала.

Складывать их запрещено: веса методикой не заданы. Дом считается сильным, когда на него указывают все три сразу; расхождение между показателями — тоже результат, и его надо назвать.

Дополнительно собираются куспиды и границы всех 12 домов (бхава-чалита) и состав каждого дома.

## 20. Контроль качества этапа

Проверить, что исходные данные (дата, время, место, пояс) идентичны во всех блоках.
При расхождении с ранее полученными материалами — не исправлять молча, а записать:

```
РАСХОЖДЕНИЕ
Показатель: …
Значение VedicHoro: …
Значение контрольного материала: …
Возможная причина: …
```

## Результат этапа — три файла

Автоматический сбор пишет их сам, в каталоге разбора:

**`01_RAW_DATA.md`** — полный технический экспорт, без интерпретации. Величины, посчитанные локально (арудхи, диспозиторы, чара-караки), помечены **[расчёт]**.
**`01_MISSING_DATA.md`** — что не получено и почему, маркерами из этого промпта. Отдельно разделены три вещи: не получено при сборе, закрыто платным доступом и «сайт не считает вовсе».
**`state/summaries/01.md`** — сводка для этапа 02.

Чара-караки считаются независимо, по наибольшему градусу, и **сверяются с тем, что показывает сайт**. Расхождение печатается блоком `РАСХОЖДЕНИЕ` в разделе 20 экспорта, а не разрешается молча.
